Where this number comes from. The plugin reads ~/.codex/auth.json — the same file the Codex CLI and the ChatGPT desktop app both write — and calls Codex's own usage endpoint with the access token stored there. It only ever reads that file, never writes it: Codex owns it, and a lost write race would sign you out of Codex itself, not just dim this key.

Signing in. Codex now ships inside the ChatGPT desktop app, so signing in to Codex there is what puts credentials in that file. The standalone codex CLI also works for this, if you have it installed.

SIGN IN — no Codex credentials found at all. Sign in to Codex from inside the ChatGPT app (or run codex once, if installed).
EXPIRED — credentials exist but the access token has aged out. Open the ChatGPT app, which owns this file, and see whether it refreshes it; if the key is still EXPIRED after that, sign out and back in to Codex inside the app (or run codex once, if installed).
API KEY — Codex is signed in with a bare OPENAI_API_KEY instead of a ChatGPT login. That has no subscription limits to report, so this key never will on an account like that — nothing to fix.
BLOCKED — the usage endpoint's own edge network returned an HTTP 403. Not a credentials problem, so signing in again will not fix it.
OFFLINE — this machine's network, not Codex or your credentials, is the problem.

Unlike the Claude key, this reads a dedicated, read-only Codex usage endpoint rather than spending a probe request — it costs nothing and does not touch your quota or your session window, so a short interval here is harmless. Polling still stops whenever no key is on screen.
