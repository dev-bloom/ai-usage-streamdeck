Picking one bucket here only changes which count the key spends its face on when there is nothing wrong to report. The key still shows UNKNOWN STATUS, NO REGISTRY, or UNREADABLE whenever one of those occurs, no matter which bucket is selected — this setting is a display preference, not a filter on whether the data can be trusted.

Press the key to peek at the sessions behind the number on screen; it reverts after a few seconds. With "All three" selected, pressing peeks at every session, same as today. With one bucket selected, pressing peeks at only that bucket's sessions — and says so, rather than listing anything else, if none are currently in it.

Hold the key to focus the terminal window of the first matching session — the same session a peek would list first. With "All three" selected, that's the first session overall, waiting before running before idle; with one bucket selected, it's that bucket's first session. If nothing matches, the key briefly says so instead of doing nothing.

A shorter hold feels snappier, but set it too low and an ordinary tap gets read as a hold — which pulls a window to the front instead of just peeking.

Focusing is exact only for Terminal.app, which can be steered to the specific tab. For VS Code and Cursor, only the app itself is brought to the front — macOS does not expose a way to select its integrated terminal pane, so the key says RAISED rather than claiming it found the exact one.
